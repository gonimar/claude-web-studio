# Web Studio для Claude Code

**Читать на:** [English](../../README.md) · Русский · [Español](README.es.md) · [Deutsch](README.de.md) · [中文](README.zh.md)

Web Studio превращает Claude Code в полноценную студию веб-разработки: 30 специализированных
агентов в трёх ярусах, 44 слэш-команды, образующие конвейер от идеи до продакшена, хуки, которые
охраняют секреты и гигиену коммитов, правила кода по путям, шаблоны документов, **датированный
справочник актуальных версий стека и лучших практик** и фреймворк для тестирования самих агентов.
Подходит и для веб-приложений, и для браузерных игр.¹

Стек: Go 1.27 · PHP 8.5 / Yii3 · TypeScript 7 / Node 24 · Angular 22 (Material, Taiga UI) ·
Vue 3.5 / Nuxt 4 · Vite 8 · GraphQL в приоритете, REST где уместно · PostgreSQL 18 · three.js r185 /
PixiJS 8 / Phaser · Vitest 4 / Playwright · Docker / GitHub Actions · OWASP Top 10:2025 · WCAG 2.2 AA.

Язык общения выбирается для каждого проекта (`/init` спрашивает); код, идентификаторы и сообщения
коммитов остаются на английском.

## 1. Установка

### Вариант A — плагин Claude Code (рекомендуется)
```bash
claude plugin marketplace add <owner>/claude-web-studio   # приватный репозиторий: gh auth login && gh auth setup-git
claude plugin install web-studio@claude-web-studio        # --scope user (по умолчанию) | project | local
```
Агенты, скилы и хуки доступны во всех проектах. Скилы вызываются с префиксом:
`/web-studio:init`, `/web-studio:help`, … Обновление: `claude plugin update web-studio`.

### Вариант B — копия внутри проекта
```bash
git clone <этот репозиторий> ~/tools/claude-web-studio
~/tools/claude-web-studio/install.sh /path/to/project            # добавьте --with-testing для тест-фреймворка агентов
```
Всё лежит в `.claude/` проекта, без зависимости от плагина, скилы без префикса (`/init`, `/help`).
Обновление — повторный запуск установщика или `/update`.

### Вариант C — новый проект из шаблона
```bash
~/tools/claude-web-studio/install.sh --new /path/to/new-project
```
Создаёт каталог, выполняет `git init`, ставит вариант B и пишет стартовый `CLAUDE.md`.

Варианты A и B совместимы: плагин даёт централизованные обновления, копия полностью правится под проект.

## 2. Первая сессия
1. Откройте Claude Code в проекте и запустите **`/init`** (плагин: `/web-studio:init`). Он спросит
   язык общения и режим ревью (`lean` для соло-работы, `full` для команд, `solo` без гейтов), затем
   создаст файлы проекта: разделы `CLAUDE.md`, `.claude/docs/` (справочник стека, шаблоны, ростер),
   `.claude/rules/`, `docs/`, `production/`.
2. **Новая идея?** — `/start`: спросит, где вы находитесь (идея / ясный продукт / браузерная игра /
   существующий код), и направит дальше.
   **Существующий код?** — `/adopt`: определит стек по lockfile'ам, проверит имеющиеся документы,
   сольёт настройки и запишет пронумерованный план адаптации.
3. Идите по конвейеру. `/help` в любой момент показывает текущую фазу и единственную следующую команду.

Конвейер: **discovery → specification → architecture → build → hardening → release → operate**
(`.claude/docs/workflow-catalog.yaml`). Гейты фаз совещательные — решаете вы.

## 3. Возвращение в новой сессии
Ничего не нужно объяснять заново. При старте сессии хук печатает ветку, последние коммиты, текущую
фазу, возраст справочника стека и — если работа не завершена — содержимое
`production/session-state/active.md` (`Task:`, `Branch:`, `Next:`, `Blocked:`). `CLAUDE.md`
загружается автоматически, поэтому язык, стек и принципы уже известны.

Типичное возвращение: прочитать сводку сессии → `/help` → продолжить командой, которую он назвал
(обычно `/dev-story S-NNN` или `/code-review --diff`). Перед сжатием контекста хук сбрасывает то же
состояние, а `/dev-story` обновляет `active.md` по ходу работы. План — `production/roadmap.md`
(список с чекбоксами); спринты и истории — в `production/`.

## 4. Как устроена студия
- **Агенты по ярусам**: два директора (Opus) решают, семь лидов (Sonnet) проектируют и ревьюят,
  двадцать один специалист реализует. Скилы сами направляют работу нужным агентам.
- **Единый протокол**: спросить при неясной спеке → предложить 2–3 варианта с ценой → решаете вы →
  показать черновик → «Можно записать?» → проверить запуском тестов и команд.
- **Ничего не считается сделанным без доказательств**: критерии приёмки привязаны к тестам,
  `/story-done` их запускает.
- **Безопасность встроена**: хуки блокируют секреты в коммитах и файлах и force-push; каждый
  чувствительный путь проходит ревью безопасности; гейт релиза требует чистых аудитов.
- **Справочник стека — источник правды о версиях**: агенты читают
  `.claude/docs/stack-reference/<технология>.md` до работы и предупреждают, если ему больше
  60 дней. `/stack-update` обновляет его из официальных источников.

## 5. Все команды
В режиме плагина к каждой добавляется префикс `web-studio:`.

**Онбординг и обслуживание**
- `/init` — разворачивает файлы студии в проекте, спрашивает язык общения и режим ревью, сливает настройки.
- `/start` — онбординг нового проекта: спрашивает, где вы находитесь, и направляет к первым шагам.
- `/help` — показывает текущую фазу, выполненные шаги и единственную следующую команду.
- `/adopt` — подключает студию к существующему проекту: определяет стек, проверяет документы, пишет план адаптации.
- `/setup-stack` — выбирает и закрепляет стек (бэкенд, фронтенд, стиль API, движок, БД, тесты, CI) с точными версиями.
- `/stack-update` — обновляет справочник стека из официальных источников с датами и предлагает план апгрейда проекта.
- `/update` — обновляет саму студию в проекте (обновление плагина или переустановка копии), сохраняя локальные правки.
- `/skill-test` — проверяет скилы и агентов линтером, поведенческими спеками и отчётом о покрытии.
- `/skill-improve` — запускает цикл «тест → правка → повторный тест» для одного скила или агента.

**Продукт и дизайн**
- `/brainstorm` — превращает смутную идею в концепт-бриф с аудиторией, отличиями и гипотезами.
- `/product-spec` — пишет спецификацию продукта по секциям: цели, пользователи, скоуп, NFR, риски.
- `/feature-spec` — пишет спецификацию одной фичи: сценарии, правила, контракт, состояния, edge cases, безопасность, критерии приёмки.
- `/ux-spec` — описывает поток или экран со всеми состояниями, текстами, доступностью и адаптивом.
- `/design-system` — определяет дизайн-токены, темы и инвентарь компонентов с маппингом на Material, Taiga или Vue-кит.
- `/game-concept` — пишет концепт браузерной игры: core loop, механики, экономика, бюджеты осуществимости, план прототипа.

**Архитектура**
- `/architecture-decision` — создаёт или дополняет ADR с вариантами, решением, последствиями и проверкой.
- `/architecture-review` — сверяет ADR, контракты, модель данных, модель угроз и спеки на согласованность (только чтение).
- `/api-contract` — проектирует контракт API до кода: GraphQL SDL по умолчанию либо OpenAPI/AsyncAPI/WebSocket-протоколы.
- `/data-model` — проектирует сущности, DDL PostgreSQL с обоснованными индексами и миграции expand/contract.
- `/threat-model` — строит STRIDE-модель угроз по поверхностям атаки с мерами и приоритетами.
- `/test-setup` — настраивает стратегию и конфигурацию тестов для выбранного стека, от unit до e2e и безопасности.

**Разработка**
- `/create-stories` — режет спецификацию фичи на истории-вертикальные срезы с матрицей «критерий → тест».
- `/dev-story` — реализует одну историю end-to-end через нужных инженеров, с тестами и проверкой критериев.
- `/code-review` — ревьюит файлы или текущий diff: корректность, стандарты, соответствие ADR, безопасность, производительность.
- `/story-done` — проверяет, что история действительно готова (тесты прогнаны, проверки зелёные, ревью одобрено), и закрывает её.
- `/sprint-plan` — планирует спринт из готовых историй, ёмкости и зависимостей.
- `/sprint-status` — отчитывается о ходе спринта по артефактам, блокерам и риску для цели.
- `/qa-plan` — сопоставляет критерии приёмки каждой истории с уровнями тестов, инструментами и файлами на спринт.
- `/tech-debt` — инвентаризирует техдолг и предлагает приоритизированные истории.

**Укрепление**
- `/security-audit` — аудитирует код и конфигурацию по OWASP Top 10:2025 с инструментами, находками по CVSS и исправлениями.
- `/dependency-audit` — аудитирует цепочку поставок: уязвимости, заброшенные пакеты, устаревшие мажоры, лицензии, пины.
- `/harden` — укрепляет заголовки, TLS, прокси, контейнеры и CI с проверкой живыми запросами.
- `/pentest` — проводит санкционированное динамическое тестирование собственного приложения проекта в зафиксированной области.
- `/perf-audit` — измеряет Core Web Vitals, бандлы, латентность API, запросы или кадры игры против бюджетов и ранжирует исправления.
- `/a11y-audit` — аудитирует доступность по WCAG 2.2 AA с axe и ручным чеклистом клавиатуры.

**Релиз и эксплуатация**
- `/changelog` — генерирует changelog из Conventional Commits и предлагает повышение версии.
- `/release-checklist` — проходит гейт релиза по доказательствам и пишет файл релиза с шагами отката.
- `/deploy` — планирует и выполняет деплой с подтверждениями, smoke-проверками и откатом, делегируя установленному деплой-скилу.
- `/hotfix` — быстро проводит срочное исправление прода от падающего теста до деплоя и бэкпорта.
- `/incident` — координирует реагирование на инцидент и пишет постмортем без поиска виноватых.

**Команды (оркестрация)**
- `/team-feature` — поставляет фичу целиком: контракт → данные → бэкенд → фронтенд/игра → тесты → ревью безопасности и кода.
- `/team-security` — проводит полный цикл безопасности: модель угроз, аудиты, укрепление, опциональный пентест, сводный отчёт.
- `/team-release` — выпускает версию: параллельные аудиты → changelog → чеклист → деплой → проверка.
- `/team-game` — собирает играбельный срез игры: симуляция, рендер, UI-оверлей, опциональный мультиплеер, замеры.

## 6. Три сценария

### A. SaaS-дашборд на Go + GraphQL + Angular
```
/init                      → язык: Русский, режим ревью: lean
/start                     → «B) ясный продукт», тип: fullstack
/setup-stack               → Go 1.27, GraphQL (gqlgen), Angular 22 + Taiga UI 5, PostgreSQL 18, Playwright
/product-spec "Аналитика команды"
/feature-spec "Участники рабочего пространства"
/api-contract F-001        → schema.graphql с Relay-connections и payload-ошибками
/data-model F-001          → таблицы, индексы, миграция
/threat-model              → поверхности: auth, GraphQL, приглашения
/test-setup --apply
/create-stories F-001      → S-001 контракт+codegen, S-002 резолверы, S-003 страница Angular, S-004 e2e
/dev-story S-001 … /code-review --diff … /story-done S-001   (повторить для каждой истории)
/team-security pre-release → /release-checklist 0.1.0 → /deploy 0.1.0
```

### B. Контентный сайт на PHP/Yii3 + Nuxt с SEO, подключённый к существующему коду
```
/init                      → язык: Русский, режим ревью: solo
/adopt                     → находит PHP 8.5 / yiisoft/* и Nuxt 4 по lockfile'ам, не находит ADR, пишет docs/adoption-plan-<дата>.md
/architecture-decision retrofit docs/adr/old-decision.md
/api-contract --style rest → OpenAPI для публичного API контента и вебхуков
/ux-spec "Страница статьи"  → состояния, тексты, доступность
/dev-story S-012           → SSR-страница Nuxt + эндпоинт Yii3, с тестами
/a11y-audit /articles      → находки WCAG исправлены
/perf-audit web https://staging.example → LCP/INP в бюджете
/harden --apply            → CSP с nonce, HSTS, лимиты Caddy
/team-release 2.3.0
```

### C. Мультиплеерная браузерная игра на three.js с сервером на Go
```
/init                      → язык: Русский, режим ревью: lean
/start                     → «C) браузерная игра»
/setup-stack game+backend  → three.js r185 (WebGPU + фолбэк), WebSocket-сервер на Go, PostgreSQL для профилей
/game-concept "Orbital Drift"   → core loop, бюджеты (16.6 мс, ≤150 draw calls), спайки
/architecture-decision "Движок и неткод"  → three.js + авторитетная симуляция на сервере 30 Гц
/api-contract --style ws   → версионированный бинарный протокол
/team-game prototype       → симуляция, рендер, UI-оверлей и сервер параллельно, замеры кадра
/perf-audit game           → draw calls, память, загрузка на 4G
/a11y-audit                → ремаппинг, субтитры, режим для дальтоников, меню с клавиатуры
/security-audit api        → Origin у WebSocket, rate limits, античит-проверки
/release-checklist 0.1.0 → /deploy
```

Четвёртый, повседневный случай — возвращение после перерыва: открыть проект, прочитать сводку
сессии, `/help`, `/sprint-status`, затем `/dev-story` для названной истории.

## 7. Поддержание актуальности
- `/stack-update` берёт свежие версии и практики из официальных источников (llms.txt Angular, Vue,
  Vite, Nuxt, Vitest, Taiga, three.js, Pixi, Babylon, Hono, NestJS; страницы релизов Go, PHP, Yii3,
  TypeScript, GraphQL; endoflife.date), переписывает `docs/stack-reference/` с датами и ссылками и
  сравнивает с lockfile'ами проекта.
- `/update` обновляет студию в проекте и сохраняет локальные правки; данные проекта
  (`docs/specs`, `docs/architecture`, `production/`, сконфигурированный `technical-preferences.md`,
  `CLAUDE.md`) никогда не перезаписываются.
- Релизы кита: поднять `version` в `.claude-plugin/plugin.json` и добавить запись в `CHANGELOG.md` —
  пользователи плагина получают обновление только при смене версии.

## 8. Тестирование самой студии
В `testing/` — каталог, рубрика качества и 74 поведенческие спеки. Запускайте `/skill-test static all`,
`/skill-test spec <skill>`, `/skill-test agent <agent>`, `/skill-test audit` или `/skill-improve <name>`
в этом репозитории или в проекте, установленном с `--with-testing`. Подробнее: [testing/README.md](../../testing/README.md).

## 9. Структура репозитория
```
.claude-plugin/   plugin.json + marketplace.json (репозиторий — одновременно marketplace и плагин)

rules/            13 правил по путям           docs/       stack-reference/, templates/, ростер, каталог конвейера, базовая линия безопасности
```

## 10. Агенты
| Ярус | Агенты |
|---|---|
| Директора (Opus) | `technical-director`, `product-director` |
| Лиды (Sonnet) | `backend-lead`, `frontend-lead`, `design-lead`, `security-lead`, `qa-lead`, `devops-lead`, `game-lead` |
| Бэкенд | `go-engineer`, `php-engineer`, `node-engineer`, `database-engineer`, `api-designer`, `graphql-engineer` |
| Фронтенд | `angular-engineer`, `vue-engineer`, `typescript-engineer`, `css-engineer`, `accessibility-specialist`, `seo-specialist` |
| Игры | `threejs-engineer`, `web-game-engineer`, `multiplayer-engineer` |
| Безопасность | `appsec-engineer`, `network-security-engineer` |
| Качество и эксплуатация | `test-engineer`, `performance-engineer`, `devops-engineer`, `tech-writer` |

Скилы-компаньоны — внешний стратегический советник или оператор деплоя — распознаются, если
