# E2E scenario: the full pipeline with branching

Executable layer over the per-skill specs: a synthetic fixture, multi-turn headless runs
(`claude -p` / `-c`), and machine assertions on the tool-event stream, the filesystem and git.
Static checks and specs validate the *text* of a skill; this layer validates *behaviour* — every
defect class below was found in live runs that the text layers passed.

## Running

```
tests/e2e.sh --branch B9          # one branch (cheapest first)
tests/e2e.sh --all                # full run, ~25–40 turns — before a release, not in run-all.sh
```

Requirements: the `claude` CLI logged in; runs cost tokens. Fixtures are generated by
`fixtures/make-brownfield.sh` and are entirely synthetic.

## Headless limits (document, don't fight)

- `AskUserQuestion` is unavailable in `-p` mode — gates degrade to text questions (the protocol
  allows this); assertions accept both forms.
- Writes to `.claude/**` are partially blocked — scaffold checks look at `docs/`, `production/`,
  `CLAUDE.md` instead.
- Language *inertia* (a session keeping English after a non-English choice) only reproduces
  interactively, because headless answers arrive as prose in the chosen language. Marked
  `interactive-only`; verify via transcript review on a real project.
