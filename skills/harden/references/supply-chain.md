# /harden — supply-chain group (Phase 2)

Read from `SKILL.md` Phase 2 (`full` and `supply-chain` modes). Facts and the checklist ids come from `.claude/docs/stack-reference/supply-chain.md`; the templates from `.claude/docs/templates/supply-chain/`. Every finding is reported as `SC-NN — status — evidence — fix`; a status is `ok`, `missing` or `partial (…)`, never a guess.

1. **Update bot config** (SC-01, SC-02). `renovate.json` (also `.renovaterc*`, `renovate.json5`) or `.github/dependabot.yml`. Present → read the release age: Renovate `minimumReleaseAge` (≥ 3 days; studio 7) and `internalChecksFilter: "strict"`; Dependabot `cooldown.default-days` (the default is 3 days when unset — say so). Grouping: Renovate `packageRules` with `groupName` for minor/patch, Dependabot `groups`; automerge only for patch/dev after checks. Missing → `SC-01 missing`, fix = `docs/templates/supply-chain/renovate.json` (Dependabot only when the project says Renovate cannot run).
2. **Actions pinned by SHA** (SC-03). `grep -rnE 'uses: [^@ ]+@' .github/workflows/` and split: `@[0-9a-f]{40}` = pinned; `@v?[0-9.]+` or `@main` = not. Local actions (`uses: ./…`) are exempt. Report the count and the unpinned lines; fix = pin each with the `# vX.Y.Z` comment, and let the update bot keep them (Renovate `helpers:pinGitHubActionDigests` is in `config:best-practices`).
3. **Lockfile policy** (SC-05). `git ls-files` for `package-lock.json` / `pnpm-lock.yaml` / `composer.lock` / `go.sum`; then `grep -rnE 'npm install|pnpm install(?! --frozen-lockfile)|composer update|mod=mod|GOSUMDB=off|GONOSUMDB=\*|--no-verify' .github/ Dockerfile* compose*.y*ml` (use `grep -P` or two greps where the look-ahead is not available). CI must run `npm ci` / `pnpm install --frozen-lockfile` / `composer install`; Go without `-mod=mod` (the default is `-mod=readonly` since Go 1.16). Also `permissions:` (SC-04): a workflow without a top-level `permissions:` block inherits the repository setting — report it as `partial`.
4. **SBOM job** (SC-06, SC-07). In the release workflow: a step that runs `syft`, `anchore/sbom-action`, or `trivy … --format cyclonedx|spdx-json` **on the pushed digest** (`@${{ steps.<push>.outputs.digest }}`), a scan step (`grype sbom:… --fail-on …`, `anchore/scan-action` with `fail-build`, or `trivy sbom`), and the SBOM attached to the release (`gh release upload`, `upload-release-assets`). An SBOM built from the build context instead of the image → `partial (build context — misses the base image)`. Missing → fix = the SBOM steps of `docs/templates/supply-chain/release-attest.yml`.
5. **Signing job** (SC-08, SC-09, SC-10). A `cosign sign --yes … @<digest>` step (or `syft attest`) with `id-token: write` on that job and `sigstore/cosign-installer`; a `--key` with a stored secret is `partial (long-lived key — keyless recommended)`; signing a tag instead of a digest is `partial (signed by tag)`. Verification before rollout: `docs/templates/supply-chain/verify-image.sh` (or an equivalent `cosign verify` with identity **and** issuer) referenced from the deploy runbook / delegate — its absence is SC-09 `missing` even when SC-08 is `ok`. Provenance: `actions/attest@v4` (or `attest-build-provenance`) with `push-to-registry: true` → SC-10; a private repository without GitHub Enterprise Cloud cannot produce it — record the reason instead of a finding.

Live evidence, when a released image exists and the registry is reachable with consent: `cosign tree <image>@<digest>` lists signatures and attestations; `cosign verify …` as in `verify-image.sh`; `gh attestation verify oci://<image>:<tag> -R <owner>/<repo>`. Without registry access every SC-08…SC-10 status is `unverified live`, as the headers are without a URL.

The group's output goes into `docs/security/hardening-checklist.md` § Supply chain (Phase 4) as the `SC-NN` table; config diffs (workflow, `renovate.json`, runbook line) follow Phase 3 and the chore lane, never the `docs:` commit.
