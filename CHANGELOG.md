# Changelog

## Unreleased
- PHP is separated from its framework. `stack-reference/php.md` (new) holds the language, the two architecture styles, tests by layer and the tooling; `yii3.md` (renamed from `php-yii3.md` — technology files carry no language prefix, like `angular.md`) keeps only what is Yii3; `symfony.md` and `laravel.md` are stubs (versions, where the layers live) to be filled by `/stack-update` and the first project on them. `php_layers` (per-context · flat) records the directory shape like `go_layers`. `php_framework` (yii3 · symfony · laravel · slim · none) is asked in `/setup-stack` and read by `/adopt` from `composer.json`; Yii3 is the only framework with a studio reference, and for the others `php-engineer` works from the official documentation and says so in every result — the framework is an Infrastructure detail, never the shape of the code. `php_architecture: layered` (`src/Domain` → `src/Application` → `src/Infrastructure`) is enforced by `docs/templates/php/deptrac.yaml`, whose `Framework` layer (the framework's namespaces) only Infrastructure may use, so `/refactor framework --dry-run` can inventory exactly what a framework change would touch; rich models use PHP 8.4 asymmetric visibility (`public private(set)`), verified on 8.4.25 to block writes from outside. Two more recorded choices replace hard-coded tools: `php_static_analysis` (PHPStan level 9 · Psalm level 1) and `php_cs_tool` (ECS with `perCs: true` · php-cs-fixer `@PER-CS`), with templates for each, PER Coding Style 3.1 named as the current edition, PHPUnit 13 as the baseline (11 out of bugfix support since 2026-02), `scripts/coverage-gate.php` reading the clover report per layer, and `composer ci` (lint → stan → arch-check → tests with coverage → coverage-gate → audit). Verified on a fixture in `php:8.4-cli`: deptrac fails on a `Domain → Infrastructure` dependency, PHPStan 9 and ECS run clean after `--fix`, the gate prints `Domain 100.0% >= 90% OK` and fails at `Application=100`. graphql-php's `BuildSchema` takes an entity named `Subscription` as the root subscription type exactly as gqlgen does, so the root-name rule now names both. `post-edit-check` hints `TEST-SLEEP`/`TEST-ERRSTR` on `*Test.php` and formats through ECS when it is installed; `/code-review`, `/architecture-review code`, `/test-setup`, `/dev-story`, `/tech-debt` and `/refactor` (modes `<namespace>`, `layout`, `tests`, `framework`) carry the PHP twins of the Go rules. Migrations are named explicitly: schema changes are migration files, never DDL in a class or a story (`rules/database.md` now also matches `src/Infrastructure/Persistence`).
- Go has two architecture styles and the studio can tell them apart. `stack-reference/go.md` gains "Architecture style" and "Layered architecture": `go_architecture: layered` (`internal/domain` → `internal/usecase` → `internal/infrastructure`, dependencies inwards only, ports declared in the domain, one struct per use case with `Execute`, rich models with unexported fields and a validating constructor, DTOs or bound domain types per `graphql_models`) next to `modular` (`internal/<domain>/`). The rule is a linter rule: `docs/templates/go/golangci.yml` (v2 — a v1 `linters-settings:` file is rejected by golangci-lint 2.x) carries `depguard` lists for the two inner layers, and the `arch-check` target in `docs/templates/go/Makefile.snippet` checks the same thing from `go list -deps`. Verified before shipping: a domain file importing an infrastructure package fails both; the `usecase` list runs in `list-mode: lax` because depguard's default mode denied `github.com/google/uuid` in a use case. `/setup-stack` asks the style, the directory shape (`go_layers`, `go_composition_root`), the router (`go_router`: chi or ServeMux), the GraphQL model mode, the value libraries the domain may import (`go_domain_allow`) and the coverage thresholds; `/adopt` records the style from the tree and offers `/refactor layout` instead of restructuring; `technical-preferences.md` has the fields. `go-engineer`, `graphql-engineer`, `backend-lead`, `/code-review` (`LAYER`, `RICH-MODEL`, `COVERAGE`, `TEST-LAYER` findings by command output) and `/architecture-review code` (dependency direction from the graph) read them.
- Tests have a layer and a gate. `go.md` "Tests by layer": domain tests without doubles, use-case tests with func-field fakes (≤ 3 methods) or `moq` and no I/O, infrastructure against containers; `docs/templates/go/coverage-gate.sh` (installed as `scripts/coverage-gate.sh` by `/test-setup`, called by `make ci`) fails the build below `go_coverage_domain` (90 %) / `go_coverage_usecase` (80 %) and prints one line per layer. Rules every Go test now follows, in `rules/tests.md` and `rules/go-code.md`: `errors.Is`/`errors.As` against a sentinel — never `err.Error() == "…"`, which breaks on the first `%w` wrap; no `time.Sleep` to wait for a result — `testing/synctest` or a polling helper with a deadline; case names in English. `post-edit-check` hints on a `_test.go` with a sleep or a string-compared error; `/code-review` reports them as `TEST-SLEEP`/`TEST-ERRSTR` from `grep` output.
- `/refactor` — the studio can change the shape of the code it maintains without changing what it does. Dry-run by default: a baseline by numbers (build, vet, lint, tests, coverage per layer, layout numbers, dependency direction, package sizes, test smells) before any question, the architecture choices as in `/setup-stack` when the mode is `layout`, a step plan whose first step is always characterisation tests and whose second is the tooling that will fail on purpose, then a plan document in `docs/ops/refactor-<date>-<scope>.md` and stories through `/create-stories`. Code moves only with `--apply S-NNN` on `refactor/S-NNN-<slug>`: every step through `go-engineer`, `go build && go test -race` after each, one green step per `refactor(S-NNN): …` commit, a red step fixed or reverted and never committed, and a before/after table that must not regress (tests, coverage, `depguard`, layout, the public API of `pkg/`). Modes `<package>`, `layout`, `tests`; no argument runs every applicable mode after asking all questions up front. Go in this version. Catalog step, spec `testing/skills/pipeline/refactor.md`, playbook § 5.5.
- The GraphQL SDL of a Go module lives at `api/schema.graphqls` and is read in place. `api_contract_path` in technical-preferences names the one schema file (`docs/architecture/api/schema.graphql` for PHP/Node projects); `/api-contract`, `graphql-engineer`, `rules/api-contracts.md` and `docs/templates/go/gqlgen.yml` point at it, and `docs/architecture/api/api-contract.md` links to it instead of holding a copy. A schema type named `Query`, `Mutation` or `Subscription` that is not the root is a BLOCKING finding before generation: gqlgen treats those names as the root operation types, and an entity called `Subscription` came out as a set of channel-returning subscription resolvers when the example from a widely shared guide was generated.

## 0.10.6 — 2026-09-17
- The agent summary counts agents, not events. 0.10.5 paired starts and stops by `aid` and printed "K starts without a stop"; a project session recounted by name, got 126 where the tool said 5, and reported it. Both numbers were answering different questions and one of them is not a question worth asking: `SubagentStart` fires on every resume of the same agent — one `aid` in a real log carries eight starts and no stop — so starts minus stops counts resumes, not losses. What the log does support is the agent: an `aid` started and never closed (five on that project, seven on another) means an agent cut off at its turn limit or still running, and the story it was given is where to look. The summary now says that, and says when it cannot: lines written before the id fields existed are named as unpairable, so a silent zero no longer reads as "clean" when it means "blind" — 139 of that project's runs are in that state. (WS-117)

## 0.10.5 — 2026-09-17
- `/sprint-status` says who did the work. `hooks/agent-stats.sh` summarises the trail `log-agent` already keeps: runs all-time and within the sprint, the top five agents (the plugin's `web-studio:go-engineer` and copy mode's `go-engineer` counted as one agent, not two), and two lines that were previously invisible without opening the log — starts with no matching stop (an agent cut off at its turn limit, or still running) and runs of non-studio agents (`general-purpose`, `Explore`), which mean routing went around the roster. ## 0.10.4 — 2026-09-17
- `hooks/session-state.sh` never destroys a state file again, and converts one on request. Shipped in 0.10.3, it rebuilt `active.md` from its own seven fields and silently dropped everything else: on the first project that used it, a 148-line working state — sprint status, fifteen lessons, tech debt, a cleanup plan with an open item — became nine lines, in a gitignored file with no archive behind it; the content came back only because the session had read it earlier. The writer now refuses any file it cannot round-trip, says how many lines it does not understand and what to do instead, and backs the file up before every write it does make (last five kept). `session-state.sh migrate` does the conversion once and deliberately: the whole previous file is archived to `production/session-state/archive/active-<timestamp>-premigration.md`, the fields it recognises — including the bold `**Task**:` spelling — are carried over, and the output says where the rest belongs (sprint file, agent memory, findings, backlog). The template says what lives in this file and what does not. The `post-edit-check` hint no longer points at the call that did the damage. (WS-115)
- `/impact` no longer writes `Next:`. `Next:` is where the session was heading and a triage is usually a detour from it, so the skill's own instruction contradicted coordination rule 7 — a project session hit exactly that, with `Next: /sprint-plan 04` pending while `/impact` was told to overwrite it. The verdict's commands go into the dated note and the closing question; `Next:` changes only when the user picks one there, because that choice is what makes it the task. (WS-116)
- `/dev-story` states that the parent does not write the story's code. The skill said "implementation via Task to the right engineers" and named them, but nothing said what happens when an agent is cut off at its turn limit — and across four stories in a row the implementing agent was spawned once, wrote nothing, and the parent wrote 687 lines itself while the stories passed. The rule is now explicit: every file through `Task` with an explicit studio `subagent_type`, a truncated agent is resumed rather than replaced, twice-truncated work is split into smaller calls, and a parent-written fallback is recorded in the story result in one line. Phase 3 plans in agent-sized steps and names the agent per step; Phase 5 compares the agents that actually started in `agent-audit.log` against the ones the plan named. (WS-087)
- CI no longer cancels runs on the default branch: `cancel-in-progress` is now conditional, after three PR merges went in while the run that was checking them was cancelled by the next push. (CWS-07)
- The settings templates stop auto-approving `pnpm dlx <any package>`: `Bash(pnpm *)` is replaced by the same narrow verbs npm already had (`install`, `run`, `test`, `audit`, `outdated`). A permission rule that runs arbitrary code from the network is not a convenience. (CWS-12)

## 0.10.3 — 2026-09-16

The skill created `docs/specs/concept-brief.md` and `/product-spec` Phase 1 read it as input, but `docs/templates/` had no brief — so each run invented a shape and the next skill looked for facts where they were not. Template, a row in `rules/docs-format.md` and a `post-edit-check` branch; an empty section is written `n/a — reason` rather than dropped. (WS-100)

A discussion that ended in rejection had nowhere to be recorded, and one ended instead with a production `Dockerfile` edited from a document session — bypassing the review, the branch and the DoD of the story that owns the file. The rejection is now a `D-NN` line in `production/decisions.md` (or an ADR marked `Rejected`), and a change to code is handed to `/impact`, `/hotfix` or a story. (WS-106)
- A finding ID is never minted without the finding. `/impact` verdicts cited `ARCH-004` for a deviation that existed in no file: the next session greps the ID and finds nothing. The row is now written into `production/findings.md` in the same turn under the same write gate, and `/story-done` checks that every `ARCH-NNN`/`SEC-NNN` named in a story card exists there. (WS-084)
- `/dev-story` no longer waits for a CI run that was never queued. With `on: pull_request` and no push trigger, a bare push starts nothing; the skill reads the triggers and opens a draft PR (`gh pr create --draft --fill`) when the PR is what starts the checks, so they run while the review happens and `/story-done` turns the draft ready. (WS-083)
- A spike has a place to live: `tools/spike-<slug>/`, gitignored and deleted when the story closes. The plugin called a spike a way to verify a decision three times over without saying where one goes, so it landed in the repository root; Phase 6 now stages the story's files by name — never `git add -A` — and names any unplanned `??` entry before committing. (WS-096)
- `/code-review` prints its routing. Reviewers were chosen by eye and the report showed only findings, so a diff touching three layers could be reviewed by one specialist with nothing to show it. Phase 2 prints the table (path → required reviewer → spawned yes/no) before the reviewers run, a skipped role costs a line saying why, and Phase 5 repeats the table with each verdict. (WS-091)
- Work outside a story has a lane. CI, linters, dependencies and developer tooling fell through the pipeline entirely: not a story, not a document, so an urgent "fix the runner" either rode a story branch or landed straight on the default branch, and what was learned was recorded nowhere. `git-workflow.md` gains the chore/infra lane (`chore/<slug>`, `ci(…)`/`chore(…)` commits, a PR with `/code-review --diff`, experimental commits squashed before the merge, the outcome recorded as a finding or a backlog entry), `/hotfix --chore` follows it without the release machinery, and the catalog has the step. (WS-093)
- A subagent running out of turns is treated as normal, not as failure. For a mid-sized story in a typed language the default limit is reached routinely; the caller used to spawn a second agent on the same task, which starts from an empty head and redoes the work. Coordination rule 7 now describes the turn budget — the signs of a truncated result, resuming the same agent rather than replacing it, and handing out work in pieces a budget holds: one layer per call, a result carrying decisions and numbers instead of a copy of the diff. `log-agent` marks a second `SubagentStart` for an agent whose `Stop` never came as `resume=1`, so the pairs stay countable. (WS-088)
- CI minutes are a budget the studio now plans against. A generated pipeline ran seven parallel jobs on every push, each with its own checkout and install and each rounded up to a minute — seven minutes per push on a 2 000-minute monthly tier, which a project burns through mid-month and then starts merging around. `tooling-devops.md` § CI states the rules (one job per toolchain, `paths:` filters, e2e and security on pull requests to the default branch, `concurrency: cancel-in-progress`, `runs-on: ${{ vars.CI_RUNNER || 'ubuntu-latest' }}` so a self-hosted runner is a variable rather than an edit of every workflow) and `/test-setup` reports the estimated minutes per run and per month. (WS-015)
- `production/session-state/active.md` has a writer instead of improvised one-liners. Skills updated it with `sed -i` and `python3 -c` inside double quotes, and nothing read the result back: a broken quote left the file unchanged and the session carried on believing it had saved its state. `hooks/session-state.sh set|note|show|clear` keeps every field of the template in order, fills untouched ones with `—`, dates each note, keeps the last ten and archives the rest to `production/session-state/archive/`, and prints the file so a failed write is visible. `/dev-story`, `/story-done` and `/impact` call it; `post-edit-check` warns when the file is missing one of its seven fields. (WS-095)
- Measurements have a home: `docs/ops/measurements/YYYY-MM-DD-<topic>.md` with the command, the environment, the raw output and the number, linked from whatever document quotes it. Coordination rule 12 says a number in a document cites an artefact, never `session-state`, which is gitignored working memory the next session may not have — until now `Notes:` was the only place measurements were written down, so a decision's evidence disappeared with the session. `/architecture-decision` and `/impact` name the file; after a compaction `session-start` prints the state's decision fields and a bounded tail of notes instead of the whole file. (WS-094)
- The startup banner stops telling configured projects that their stack is not configured. `session-start.sh` kept the whole-file grep for `TO BE CONFIGURED` that 0.10.2 replaced in the installer, so every session of a fully configured project opened with "Stack not configured — run /setup-stack or /adopt" because the template's header comment mentions the placeholder. That is not cosmetic: `/help` routes a project with code and an unconfigured stack to `/adopt full`, which would rewrite the very file WS-082 was about. "Configured" now has one definition, `hooks/prefs.sh`, shared by the banner and the installer, and `/help` names the `**Type**` field instead of the placeholder. (WS-113)
- `validate-commit` reads the message of a `git commit -F` too. For `-F` the hook set the message to an empty string, so the documents lane was invisible — a commit staging nothing but `.claude/docs/coordination-rules.md` with the subject `docs: …` was warned about "committing directly to 'master'" — and the Conventional Commits check was skipped altogether: blind rather than lenient. `-F` is not an exotic corner: `git commit -m` runs command substitution on backticks, so every multi-line message with inline code, which is what a documents commit looks like, goes through it. The hook now reads the file, or the heredoc body of `-F -`, and `validate-push` (which always read the subject from git) stops disagreeing with it. (WS-112)

Found on a real project in the first run after the release. (WS-111)

The form without `--json` is documented as unusable for this: its blocks carry Version, Scope and Status and no project path. Spec case update 12. (WS-110)

## 0.10.2 — 2026-09-16
- `/update` no longer overwrites a configured `technical-preferences.md`. In plugin mode the skill had no seeding command, so a session copied `docs/` wholesale (`cp -r <cache>/docs/* .claude/docs/`) and replaced a filled stack — type, pinned versions, the rationale for rejected upgrades, the ADR log — with the template; the run then reported "project data unchanged". Seeding is now a single command, `install.sh <project> --seed-only` (docs/ and rules/ only, agents/skills/hooks come from the plugin update), and Phase 3 verifies the result with `git diff --quiet` before it may claim the file was untouched, restoring it when it was not. The installer's own guard was broken as well: it looked for `TO BE CONFIGURED` anywhere in the file, while the template's header comment mentions the placeholder — so every configured file looked unconfigured and was overwritten in copy mode too. "Configured" now means the `**Type**` field is filled, the same predicate `workflow-catalog.yaml` uses, and the installer prints `technical-preferences.md: kept (configured)`. Without `rsync` the exclusion is real instead of a warning after the fact. Installer tests cover a fixture that keeps the header comment, the no-rsync path and `--seed-only`; spec case update 9. (WS-082)
- `/update` Phase 2 updates the plugin in the scope where it is installed: `claude plugin update web-studio --scope <scope>`, taken from the `claude plugin list --json` output Phase 1 already reads (`-y` in a non-interactive run). The bare command assumes `user` scope and stops the run with `Plugin "web-studio" is not installed at scope user` in every project installed with `--scope local`. Spec case update 10. (WS-108)
- `/update` recognises a third mode: a copy-mode install left in place under the plugin. Plugin and copy mode were described as exclusive, so a project could run last month's skills from `.claude/skills/` for weeks — project copies shadow the plugin by name, and only the `web-studio:` prefix reached the current version. Phase 1 now reports `HYBRID INSTALL`, establishes the copy's real version by comparing it with the cached plugin versions instead of believing `.claude/.web-studio-version`, and lists the files that match no version — those are local edits and the project's own kit, everything else is removable without loss. Phase 3 offers the removal as its own gate, moves agent memory from `<agent>` to `web-studio-<agent>` (appending `MEMORY.md` pointers), checks whether `.claude/settings.json` wires the copied hooks at all, and ends with "restart the session" — removing `.claude/skills` empties the skill registry of the running session. The stamp is written only in copy mode: in plugin mode `claude plugin list --json` is the source of truth, and a stamp naming a version whose files are not in the project is worse than none. `/help` prints one line when project copies shadow the plugin. Observed on a real project: a stamp reading 0.5.8 over files from 0.4.3, then 0.10.1 while only `docs/` and `rules/` had been reseeded. Spec case update 11. (WS-109)
- `validate-commit` no longer passes everything in silence when the staging happens in the same Bash call. The hook read the index, and `git add secrets.env && git commit -m "…"` — the form the studio's own skills use — leaves the index empty at the moment the hook runs, so the secret-file block, the secret-string block, the lockfile and TODO warnings and the branch checks all did nothing. The hook now resolves what the command's `git add` segments would stage (`git add --dry-run`) and reads the content from the working tree, so a staged-in-the-same-call `.env` or a leaked token is blocked exactly as before. (WS-101)
- `validate-commit` accepts a story ID as the Conventional Commits scope: the class `[a-z0-9/_-]` rejected capitals, so `feat(S-019): …` — the message `/dev-story` itself generates — always warned, which is how a warning becomes noise. A capitalised *type* (`Feat: …`) is still flagged. (WS-102)
- `validate-push` knows about the documents lane. Pipeline documents live on the default branch by design and `validate-commit` lets them through, but every push then warned "pushing directly to 'master'", including the push that carried exactly those documents. The push hook now checks the commits that would travel: all of them `docs:` and touching documents only → no warning; anything else, or a range it cannot establish → the warning stands. The lane is defined once, in `hooks/docs-lane.sh`, so the two hooks cannot drift apart. (WS-103)
- `log-agent` stops calling built-in tooling a lost agent: a Stop event with no agent type is logged as `builtin` rather than `unknown`, so Start/Stop pairs in `agent-audit.log` stay countable and an unpaired studio agent is visible again. (WS-089)
- `/help` stops inventing commands. The hand-off named `/dev-story complete S-007`, which does not exist — a story is closed by `/story-done` — and a command shape invented by the studio's own orientation skill sends the user to a dead end with the studio's authority behind it. Every command in the answer now comes from the catalog or from a skill's `argument-hint`, and the session-start context (merged branch, template placeholder, stale stack reference, an open `Gate:`) is repeated as one line each instead of being left in the startup block the user already scrolled past. (WS-052)
- Calibration is one sample with one name. `/sprint-plan` scaled the next sprint by a ratio over "every closed story" while `/retrospective` computed its own over one sprint, and the plan's text claimed the two were the same number. Both now read the last six closed stories of the roadmap that carry `~Nh` and `⏱ Nh`; the retrospective additionally prints the sprint's own ratio, labelled, so the two are never confused. (WS-086)
- `/sprint-plan` moves the selected stories out of the Backlog block instead of copying them into the sprint: a story listed in both places made every `<summary>` count on the roadmap wrong from then on. The write step recalculates both counts and states them (`Backlog: N → M, Sprint: 0 → K, overlap none`). (WS-107)
- A reviewer now gets something it can actually read. `/architecture-decision` required that "each reviewer receives the full draft text", which does not fit a Task prompt and was never once done: the draft goes to a session file and the reviewer receives its path plus the requirement to quote the ADR title and the two Decision lines back — the quote being the evidence of reading. A verdict with no quote is returned once, then reported as unread rather than counted. The same rule is in `coordination-rules` § Subagents for every skill that reviews a draft. (WS-097)
- `subagent_type` is always a studio agent. A three-round "final assessment" of an ADR draft was performed by a generic agent with a model override: no project rules, no agent memory, no role in the audit log. Wanting a stronger opinion changes the model of a roster agent, never the agent itself. (WS-104)
- A `FAIL` that was edited is reviewed again. A product spec went out as `FAIL` with four blocking factual errors, was rewritten "according to all eight comments" and recorded as done — checked by nobody. The same verifier now gets a short second pass, the document's verdict is the last review's, and a skipped re-review is written down as `FAIL (edits unverified)` instead of quietly becoming a pass. Same rule in `/feature-spec`. (WS-098)
- An idea that leaves the backlog sideways is closed anyway. `/impact` run directly on a backlog entry left `I-003` open for weeks while the work was already done, because only `/backlog promote` marked entries. `/impact` now writes its verdict back into the entry under the same write gate, and `backlog review` recognises an entry whose text matches a spec, ADR or verdict written later. (WS-099)
- `/story-done` proves the roadmap carries the numbers. For three closed stories in a row the `⏱` time and the `🔗 PR` link travelled only as far as the chat answer: neither the sprint line nor the `## Docs` row received them. The skill now re-reads both places after the edit and reports a mismatch as an open DoD item. (WS-092)
- `go-engineer` leaves a trace of the stack reference. "Read `stack-reference/go.md` first" was followed in about half of the runs, and nothing could tell the difference. The result now starts with `Reference: stack-reference/go.md (updated: YYYY-MM-DD)`, carrying the date from the file that was opened; no line means the reference was not read. (WS-105)
- Spec cases for all of the above: help, sprint-plan (2), retrospective, architecture-decision, product-spec, impact, story-done, and the go-engineer agent spec.
- The hooks see what the skills actually do. `consent-guard`, `secret-guard`, `impact-guard` and the document-format part of `post-edit-check` were registered on `Write|Edit` only, while the skills author documents with `cat > file <<EOF` and `python3 - <<PY` — so the entire guard lane watched a tool nobody used. Measured on one real day in a project: 588 Bash calls, 15 Writes (all into a scratchpad), 0 Edits, 0 guard lines of any kind, and `touch .claude/.write-consent` executed 176 times with nothing left to check it. The four hooks now also run on `Bash`, and `hooks/written-paths.sh` is the single place that answers "what would this command write" — redirections, `tee`, `cp`/`mv`/`install`, `sed -i`, and a heredoc body that writes a file itself (`open('f','w')`, `writeFileSync`). A configured `.env` written through a heredoc is blocked, a token pasted into a heredoc body is blocked, a roadmap written without a fresh consent marker warns, and a document written that way gets its format check. Code formatters stay on the Write/Edit path, where the call names one file and means it. `coordination-rules` rule 7 now says documents are written with Write/Edit: the Bash lane is a safety net for literal paths, not a licence — a path built from a variable is still invisible.
